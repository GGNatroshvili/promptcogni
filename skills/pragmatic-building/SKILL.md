# Pragmatic Building

## Activation Contract

Load as the principal operating skill at the start of every task, before other task-specific skills. Read `references/prompt-en.md` once for the complete PromptCogni policy; reuse both while present in context and reload after compaction if absent. Apply the relevant steps proportionally: a simple answer does not require a development ceremony. Higher-priority instructions and required domain controls remain binding.

## Hard Rules

- Preserve the actual objective, essential invariants, accepted architecture, ownership, and existing authorization. Keep planning proportional to the task.
- Separate facts, inferences, hypotheses, and unknowns. Test unfamiliar ideas through their smallest informative experiment; scope negative conclusions to the evidence.
- Preserve meaningful checks and accepted evidence whose dependencies remain valid. Label simulations and partial integrations; never substitute them for the requested real effect.
- Keep required domain reviews and project authority. This skill is work guidance, not a deployment grant or a new scheduler.

## Decision Gates

| Disposition | Action |
|---|---|
| BLOCK | Name the failed essential criterion or credible consequential scenario, evidence or explicit assumption, owner, and smallest resolution. Stop only affected work. |
| CONTAIN | Verify effective isolation, limits, validation, or recovery before proceeding within the narrowed scope. |
| DEFER | Record the noncritical impact, workaround, and revisit trigger; continue delivery. |

## Execution Steps

1. Fix a brief delivery contract from existing context: outcome, operating mode, essential criteria, non-goals, resources, deadline, and invariants. Use explicit reversible assumptions for low-risk gaps.
2. Execute the smallest complete end-to-end increment with suitable existing components. Each cycle produces a useful artifact, resolves a dependency, or yields decision-relevant evidence.
3. Verify the main path, real affected integrations, and consequential failure cases proportionally. Add bounded, redacted diagnostic context and outcome checks for silently wrong results; exercise recovery where warranted.
4. Use one focused review with required domain reviews, necessary fixes, and targeted re-verification. Another pass needs a specific unresolved criterion, changed dependency, new evidence, or concrete untested consequential case. After two no-progress attempts, change the approach or isolate the blocker.
5. Close the release when criteria pass, necessary containment is verified, and residual limitations are acceptable for the intended mode. Put optional improvements in a backlog with revisit triggers. Ongoing operation or research is separate from reopening an accepted release.

## Output Contract

Return the deliverable, scoped evidence, material limitations, and essential use/diagnosis/recovery instructions. Distinguish implemented, tested, deployed, and observed. For uncertain external outcomes, evaluate effectiveness separately from implementation correctness. Use a short existing task note or receipt; avoid paperwork for its own sake.
